## 取得後にこのサイトで変更する場所（未実施）

単に住所を追加するだけでは、Googleログインや保存が動かなくなるため、次を一緒に切り替えます。

| 場所 | 操作・入力 | 成功時の状態 |
|---|---|---|
| Cloudflareのドメイン画面 | 取得したドメインが同じアカウントで有効になったことを確認 | DNSの状態が有効 |
| Workers & Pages → news-pocket → Settings → Domains & Routes → Add → Custom Domain | 確定したホスト名を入力 | 新URLでHTTPSのサイトを表示。DNSと証明書はCloudflareが作成 |
| wrangler.jsonc | routesにcustom_domain:true、APP_ORIGINとCONTACT_URLを新URLに変更 | Worker側の変更操作の送信元と問い合わせURLが新URLと一致 |
| scripts/deploy.mjs | 現在はworkers.dev以外を拒否するため、取得済みの正しいHTTPSホストを許可する検査へ変更 | 無料プラン確認を維持して公開できる |
| Google Cloud → news-pocket-511705 → Google Auth Platform → クライアント | 新URLの /api/auth/callback を承認済みリダイレクトURIへ追加 | 新URLでログインし、同じ利用者の保存記事が読める |
| Google Auth Platform → ブランディング | ホーム・プライバシー・利用案内のURLを更新。必要なドメイン確認も実施 | 同意画面の案内が新URLを指す |
| GitHub → iori-doiya/news-pocket → Settings → Secrets and variables → Actions → Variables | SITE_URLを新URLへ変更 | 記事配信と日次整理が新URLへ到達 |
| 専用クラウド更新タスク・運用資料 | 旧URLの参照を更新 | 重複確認・反映先・説明の住所が一致 |
| scripts/recovery-drill.mjs | 復旧確認の参照先を新URLへ変更 | 次回の復旧確認も新URLを使う |

セッション（ログインを維持する記録）は住所ごとに保存されるため、新しい住所で再ログインが必要になる場合があります。同じGoogleアカウントで入れば、同じD1の保存先を使う設計です。実際のログイン・保存・問い合わせ・記事配信を新URLで確認するまでは、移行済みと扱いません。旧URLからの転送も、その確認後に設定を検討します。

[CloudflareのCustom Domains公式手順](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/)で、有効なCloudflareゾーンが必要なこと、DNSと証明書を自動作成することを確認しました。
