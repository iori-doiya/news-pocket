## 現時点の結論

「技術的にデータを読める」「公開サイトで使える」「AIへ送れる」「要約を一般公開できる」は別の条件です。今回、公式RSSの存在と実際の応答を確認できたのはYahoo!ニュースとITmediaの3媒体です。**6媒体の本文を自動取得し、外部AIで要約してこの公開サイトへ表示することを、追加費用0円で許されると確認できた経路は、現時点ではありません。** 技術的にすべて不可能という意味ではありません。

公開アプリへの組み込みやAI要約の許諾を取る方法は下記に示します。問い合わせはまだ送っていません。契約・有料サービスの申込み、ログイン情報の転送も行っていません。

|---|---|---|---|
| Yahoo!ニュース | 公式RSSの見出し・URL・日時。本文は原掲載社から許諾を得た経路で受け取る | RSSは本文なし。情報提供元ごとの二次利用・AI送信・要約公開の確認が必要 | 未許諾・無効 |
| ITmedia AI＋ | 公式aiplus.xml。本文が必要なら公式記事配信サービス等を個別相談 | RSS組み込み・改変は個別相談。AI処理と要約の一般公開を含む許諾は未取得 | 未許諾・無効 |

## 1. Yahoo!ニュース

**取得方法**：公式の[RSS案内](https://support.yahoo-net.jp/PccNews/s/article/H000011243)から配信URLを確認し、必要なカテゴリのRSSを読む。調査した主要トピックスは `https://news.yahoo.co.jp/rss/topics/top-picks.xml`。1回の読み取りでHTTP 200・8項目を確認。項目はtitle（見出し）・link（URL）・pubDate（日時）・commentsで、description（説明文）や記事本文はありませんでした。件数や項目は変わる場合があります。

**AI要約まで行う方法**：RSSから掲載元と元記事を特定し、情報提供元が認める本文データの取得方法を用意する。その会社に、本文取得・Cloudflare Workers AIへの送信・要約の作成・公開サイトへの表示・保存と共有再利用の可否を確認する。許諾を得た記事だけを扱う。Yahoo!から新聞社などの本文を一括で自由に使えると推定しない。

**条件**：[公式の二次利用案内](https://support.yahoo-net.jp/SccNews/s/article/H000006460)では、掲載情報の二次利用は情報提供元の了承が必要とされる。通常のテキストリンクと、記事内容の転載・加工は別。この記事取得のためにYahoo!検索の規約をニュースの規約として引用することはしない。

**難しい場合の代替案（未実装）**：Yahoo!ニュースを開くリンク集、本人が選んだ記事URLと自分のメモだけを保存する方式。本文は元サイトで読む。見出ししか取れない場合は「関連記事へのリンク」と表示し、背景や事実を推測してAI要約を作らない。

## 2〜4. ITmediaの3媒体

**公式RSS**：[公式RSS一覧](https://corp.itmedia.co.jp/media/rss_list/)にある次の3本を確認した。

| 媒体 | RSS URL | 1回の技術確認結果 |
|---|---|---|
| AI＋ | `https://rss.itmedia.co.jp/rss/2.0/aiplus.xml` | HTTP 200、20項目、最初の説明文は99文字 |
| NEWS | `https://rss.itmedia.co.jp/rss/2.0/news_bursts.xml` | HTTP 200、50項目、最初の説明文は110文字 |
| ビジネスオンライン | `https://rss.itmedia.co.jp/rss/2.0/business.xml` | HTTP 200、20項目、最初の説明文は191文字 |

いずれもtitle・link・description・pubDateを確認した。本文全文ではない。調査のために1回読んだだけで、記事DBへの登録・公開表示・AI送信はしていない。説明文の文字数は調査時の最初の項目だけの値で、全記事共通ではない。

**取得とAI要約まで行う方法**：まず[RSS利用条件](https://corp.itmedia.co.jp/media/rss_condition/)に記載された窓口へ、3媒体のRSSをニュースポケットへ組み込むことと、説明文を外部AIへ送って加工・公開することをまとめて確認する。本文を要約したい場合は、[公式記事配信サービス](https://corp.itmedia.co.jp/media/contents_feed/)の全文データなどを相談する。このサービスは有料と明記され、全文または見出し・URL・リードなどをXML（RSS）で配信し、IP制限またはBasic認証に対応する。通常のRSSが読めることは、全文配信やAI利用の許諾ではない。

**条件**：RSSのアプリ組み込みは相談対象。発信元の非表示や一部削除を含む改変・翻案・翻訳などが禁止事項に挙がり、希望する場合は個別相談とされる。AI要約を公開する許諾が自動的に付くとは確認できない。本文契約では、3媒体の対象範囲、第三者の執筆記事、広告、出典、削除要求、保存期間、AI処理を改めて決める。

**難しい場合の代替案（未実装）**：許可範囲に従う個人用RSSリーダーで読む方法、またはこのサイトを3媒体へのリンク集にする方法。個人用に閉じれば無条件でAI要約できるとは扱わない。無料の組み込み・AI利用が認められなければ、0円を優先してAI要約を有効にしない。

## 5. SmartNews

**取得方法の調査結果**：個人がSmartNewsアプリで見る一覧を、外部アプリが読み出す一般向けAPI/RSSは確認できなかった。[SmartFormat](https://publishers.smartnews.com/hc/ja/articles/360040070613-SmartFormat%E3%81%A8%E3%81%AF%E4%BD%95%E3%81%A7%E3%81%99%E3%81%8B)は媒体からSmartNewsへ記事を入稿する仕組みで、読み出すAPIではない。[Marketing API](https://ads.smartnews.com/developers)は広告向けで、ニュース本文取得APIではない。

**AI要約まで行う方法**：SmartNewsへ、外部アプリへの記事一覧・本文の提供、外部AI処理と要約公開を許諾する連携の有無を確認する。配信社からの本文受領に切り替える場合も、利用者が選んだ配信社と利用条件を確認してから行う。

**条件**：[利用規約](https://www.smartnews.com/terms)の日本向け部分では、正規の利用手段以外の取得・転載、認められていない自動化プログラムによる抽出・分析、アクセス制御の回避などを禁止している。SmartNews自体の生成AI機能の規約は、このサイトで外部AI処理するための許諾ではない。許可のない内部API解析やアプリ通信の再利用は実施しない。

**難しい場合の代替案（未実装）**：本人がアプリの共有操作で選んだ元記事URLを保存し、元サイトへ移動して読む。URLを受け取っただけで本文のAI処理が許されるとは扱わない。元配信社のRSSを使う場合も、その媒体を勝手に追加せず、選んでもらった後に条件を確認する。

## 6. 日経電子版

**取得方法**：日経電子版の購読IDで本人が読む方法と、プログラムが本文を使う方法は別。[日本経済新聞社の記事データ提供](https://nkbb.nikkei.co.jp/article/)に、生成AI等での利用を相談する経路がある。[NIKKEI KAIの公式案内](https://nkbb.nikkei.co.jp/kai/)にはKAI AgentのMCP/API連携、[関連案内](https://nkbb.nikkei.co.jp/kai/base10/)には利用者自身の生成AI環境へのコンテンツデータ提供も記載されている。機械連携の選択肢がないわけではないが、契約内容・費用・一般公開権は未確認。対象記事、見出し・本文・書誌情報、提供形式、認証、更新頻度、AI処理、公開表示の可否を相談する。一般無料の本文APIや日本語電子版のRSSが確認できたとは記載しない。Nikkei AsiaのRSSは今回指定された日本語電子版と別なので代用しない。今回は日経電子版を直接対象とし、以前の「X・日経電子版」という混同した設定を修正した。X APIはこの調査に不要。

**AI要約の条件**：[通常の記事利用条件](https://nkbb.nikkei.co.jp/reprint/note/)には生成AI等への入力・学習・解析・加工目的を認めない旨が記載されている。通常の転載申請や電子版購読だけでCloudflareのAIへ本文を送らない。AI向けの記事データ契約と、要約を一般公開する条件を別途確認する。許諾・料金は未取得。[NIKKEI KAI](https://nkbb.nikkei.co.jp/kai/)等の日経側のAIサービスがあっても、このサイトでの再公開権が付くとは扱わない。

**難しい場合の代替案（未実装）**：日経電子版を開くリンクと本人のURLメモだけを持ち、本文は公式サイトで読む。日経側のAIサービスを使う案はあるが、追加費用0円を確認できていないため申し込まない。購読画面のCookieやIDをサーバーに置く方法や、有料記事の制限を回避する方法は採用しない。

## 許諾後にこのサイトへ接続する順序

1. 上記の公式窓口へ、次の確認文案を使って本人が問い合わせる。この作業ではまだ送っていない。
2. 返信や契約で、取得・公開・AI入力・要約公開の4点、費用、保存期間、出典表記、第三者記事の扱いを確認する。無償で許可されない場合は、0円の前提を優先する。
3. `config/sources.json`の該当媒体だけを設定する。RSSのURLが入っていても、現在はenabled=false・権限項目はfalse。確認できた範囲だけをtrueにし、根拠と確認日を残す。
4. `src/feed.mjs`等を実際に許可された提供形式へ合わせる。RSSの説明文しかない場合はその範囲を表示する。本文契約の認証値はSecretsへ登録し、公開コードへ入れない。
5. ローカル検証→手動収集→出典・本文範囲・AI出力の確認後に本番収集を再開する。媒体未確認の状態を「接続済み」と表示しない。

### 問い合わせの確認文案（未送信）

個人が運営する無料のニュース閲覧Webアプリ「ニュースポケット」で、貴社の指定媒体の記事を扱うことを検討しています。次をそれぞれ確認したく、ご利用可能な配信方法と条件をご教示ください。

- 見出し・URL・日時・説明文を定期取得し、公開サイトで一覧にすること
- 本文データを取得・一時保存すること、その公式の提供方法
- Cloudflare Workers AIのQwenモデルで、学習用途ではなく要約を生成するために外部送信すること
- 日本語要約を元記事・媒体名・出典リンクとともに公開し、同じ要約を利用者間で再利用すること
- 第三者記事・写真・広告の除外方法、保存期間、削除依頼への対応条件
- 利用料が0円で可能な範囲。有料の場合、今回は申し込まない予定であること

「AI学習に使わない」は、外部AIへの入力や要約公開の許可とは別です。許諾内容に書かれていない用途を、こちらの解釈だけで広げません。

## 今回変更した上限と未完成の範囲

新規AI要約の設定は1人30件・サイト全体50件／日本時間の日付ごと。失敗を含む試行は50件、UTC日の保護用予約は7,500 Neuronsを維持し、新規試行の予約を150にした。過去の利用実績は消さない。失敗や無料枠の消費状況によって50成功より先に止まる場合がある。現在は許諾確認済み媒体0件のため、設定を増やしても新しい記事のAI要約はまだ利用できない。

上限変更はアプリとD1トリガーの両方に反映する。新しい移行は`migrations/0005_summary_limits.sql`。旧4媒体の記事・要約を公開から外すが、本人の保存記録を取り下げ操作だけで消さない。期限切れの問い合わせ・一時データ等の整理は続ける。リンク集・URL共有受信・メモ整形などの代替案は、方法の提示までで、実装済みではない。
